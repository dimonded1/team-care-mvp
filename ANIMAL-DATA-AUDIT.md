# Каталог и мэтчинг подопечных из Bitrix24

Дата контрольной синхронизации: 2026-07-28.

## Как работает поток данных

Браузер никогда не обращается к Bitrix24 напрямую. Серверный read-only скрипт
проходит все страницы настроенных воронок, отбирает только опубликованные
карточки без запрета на показ и сохраняет безопасный каталог:

- `integrations/bitrix/animalCatalog.generated.json` — полный публичный каталог
  и статус готовности к мэтчингу;
- `src/data/bitrixAnimals.generated.json` — компактный клиентский снимок только
  тех животных, для которых проверен редакционный профиль мэтчинга;
- `public/assets/animals/bitrix/` — локальные оптимизированные фотографии
  match-ready животных без временных подписанных Bitrix-ссылок.

Синхронизацию следует запускать по расписанию на сервере и перед сборкой
клиента. Доступность Bitrix не влияет на открытие игры пользователем.

## Какие данные переносятся автоматически

- стабильный CRM ID и воронка;
- кличка;
- вид и пол из перечислений;
- дата рождения;
- публичное описание;
- публичные поля характера и поведения;
- наличие основного и дополнительных фото;
- публичная ссылка на профиль, если она заполнена;
- флаги публикации, блокировки и доступности для опеки.

Медицинские заметки, назначения, лекарства и внутренние комментарии не
попадают в публичный каталог или браузер.

## Почему не все 436 сразу участвуют в мэтчинге

Тест использует семь смысловых осей: энергия, общительность, инициатива,
терпение, режим, уважение дистанции и готовность к сложному знакомству.
Bitrix не хранит эти значения в едином структурированном виде. Автоматически
выдумывать числа из свободного описания небезопасно: один и тот же текст может
быть неполным, устаревшим или описывать прошлое состояние животного.

Поэтому `src/data/animalEditorial.json` является явным проверяемым слоем. После
добавления туда профиля по стабильному Bitrix ID животное автоматически войдёт
в клиентский каталог при следующей синхронизации. Логика теста и код приложения
при этом не меняются.

## Эксплуатация

1. На сервере хранить webhook и поля только в `.env` с правами `0600`.
2. Запускать `npm run sync:animals` по расписанию, например раз в ночь, и перед
   production-сборкой.
3. Проверять изменения полного каталога и очередь `needsEditorialProfile`.
4. Добавлять проверенные профили в `src/data/animalEditorial.json`.
5. После синхронизации выполнять `npm test`, `npm run test:server` и
   `npm run build`.

Скрипт пишет JSON атомарно и прерывает обновление клиентского снимка, если уже
проверенное животное исчезло из доступного каталога или лишилось обязательных
данных.
