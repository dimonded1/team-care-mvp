# «Команда заботы»: выполнено и осталось проверить

Актуально на 15 сентября 2026. Обычный маршрут с четырьмя онлайн-играми, не «4 лапы». Изменения локальные, без коммита и публикации. Предыдущие исправления сохранены.

## Реализовано

| Область | Изменения |
| --- | --- |
| Прогулка | После живого завершения снимается перехват касаний/стрелок, освобождается pointer capture и прокрутка. Цель до старта, различимый клещ, ясный итог и «Сохранить станцию». Сохранение прогресса и полный сброс после укуса сохранены. |
| Знакомство | Одна видимая ситуация + четыре видимых действия, заметная рамка, объяснение до явного продолжения. Старые сохранения совместимы, быстрый третий тап блокируется. |
| Визит | Компактнее иллюстрация на телефоне, комментарии с явной кнопкой, выделенный вывод и итог пяти шагов из существующего контента. |
| Здоровье | Номера и подписи зон, альтернативные кнопки выбора, компактнее карта/вопрос и итог. Медицинская логика не менялась. |
| Мэтчинг | Центрированная подпись «Выберите ответ», защита от запоздалого ответа после Back. Карточка теперь растёт с увеличенным текстом, а не обрезает его. |
| Reveal | Длинный тестовый пример помещается; отложенная загрузка фото не отключает CTA. Результат сохраняется при refresh/Back. |
| Орбита | Не начато / в процессе / готово к сохранению / пройдено; крупнее подписи, раскрываемый список станций. Защита от двойного выбора с освобождением таймера. |
| Опека | Сохранён зелёный экран, раскрытый блок помощи, рабочее меню. |
| Финал | Статусы загрузки/готовности/ошибки, повтор, пояснение скачивания на iPhone. Генератор загружается отдельно. Ожидание ограничено 20 секундами, уход отменяет загрузку ресурсов, устаревший результат не перезаписывает новый. |
| Форма | Синхронная защита submit сохранена. Ожидание ограничено 25 секундами, при ошибке поля остаются в памяти. Сервер различает pending/completed: повтор во время отправки получает 409, а не ложный успех; после подтверждения повтор не создаёт новую отправку. |
| Общий UI | Согласованы Back, подтверждение станции, focus и объяснения. Без новых библиотек и тяжёлых изображений. |
| Производительность | Орбита не обновляет DOM непрерывно при паузе, reduced motion и скрытой вкладке. Отдельный генератор карточки; большой основной чанк пока остаётся. |
| Сопровождение | Актуальный smoke для обычного пути, отдельные режимы живого завершения. Локальная обезличенная диагностика по запросу. |

## Проверки

Основные команды: `npm run test`, `npm run test:server`, `npm run build`, `git diff --check`.

15 сентября повторно: 1018 тестов приложения (27 файлов) и 28 серверных тестов прошли; сборка и diff-check прошли. Основной JS — 1137,92 kB (gzip 245,89 kB), отдельный генератор карточки — 7,16 kB. Предупреждение о большом чанке остаётся.

Полный браузерный прогон по времени 15 сентября прошёл: обычные четыре игры, живое завершение, физические touch-свайпы в обе стороны после завершения, refresh, верхний Back, повторный вход и сохранение станции, форма 503 → повтор без двойного POST. На финале при ширине 320/360/390/430 px и desktop нет горизонтального overflow и кнопок меньше 44 px. Артефакты: /tmp/team-care-sept15-timer. Зафиксирована длинная задача 529 мс в текущем документе: это требует отдельного профилирования, не считается доказательством плавности слабого Android.

Второй полный прогон 15 сентября тоже прошёл: все предметы + финиш с обычными анимациями, один укус с восстановлением игры, та же проверка прокрутки/Back/refresh/сохранения. Задержка модуля карточки на 22 секунды вызвала ошибку по таймауту; повтор успешно создал карточку. Артефакты: /tmp/team-care-sept15-resource. Неожиданных ошибок консоли нет; единственная разрешённая 503 — намеренно подменённый ответ формы. Проверка задержки только логотипа первоначально не сработала из-за повторного использования ресурса; сценарий исправлен на задержку ленивого модуля, без изменения приложения ради теста. Для совместимости параметр называется `SMOKE_FINAL_CARD_LOGO_DELAY_MS=22000`.

`npm run smoke` (или `smoke:current`) проверяет актуальный путь. Старый сценарий сохранён как `smoke:legacy`, не является критерием релиза. Локальный сервер задаётся `SMOKE_URL`, артефакты — `SMOKE_ARTIFACTS_DIR` (по умолчанию /tmp/team-care-current-review).

- `SMOKE_MAZE_COMPLETION=timer` / `collect`: живой выход по времени / сбор всех предметов и домик. Сбор использует модель выбора пути, но настоящие стрелки, не подстановку готового состояния.
- `SMOKE_REDUCED_MOTION=0`: обычные анимации; по умолчанию reduced motion.
- `SMOKE_FOCUS=quiz-reveal SMOKE_TEXT_SCALE=2 SMOKE_REVEAL_PHOTO_DELAY_MS=3000`: расширенная проверка вопросов и reveal.

При OS-scale 1 и 2 Chrome оставил текст 29 px. Поэтому тест явно применяет синтетическое удвоение до 58 px и помечает его именно так, не как реальный системный шрифт телефона. До исправления первый вопрос обрезался: scrollHeight 500 против clientHeight 343. После исправления все 11 вопросов помещаются, кнопки доступны и имеют размер 96×50 px. Артефакты: /tmp/team-care-200pct.

Фото на reveal задержано на 3 секунды, CTA остаётся доступным. Синтетическое имя «Антонина Викторовна» помещается в две строки; в данные подопечных оно не добавлялось.

Полные прогоны 10–11 сентября проверили оба исхода прогулки, refresh/Back/Forward, прокрутку и подменённую форму (503 → успешный повтор, тот же request ID, без лишнего POST). Это Chrome на компьютере, не реальные Android/iPhone. В одном прогоне зафиксирована длинная задача 64 мс — отсутствие всех задержек не заявляется. Временные снимки могут удаляться системой.

Новый `server/contact-flow.node-test.mjs` проверяет сервис/адаптер/дедупликацию с подменённым транспортом: таймаут, повтор, параллельный запрос и сбой первого запроса. Это **не проверка реального HTTP handler или доставки в Bitrix**. Production-контакты не создавались.

## Диагностика и персональные данные

`?diagnostics=1` включает только локальные коды завершения прогулки, доступности/исхода формы и ошибки карточки. Только код и время: без ФИО, телефонов, email, ID животного, тела запроса и текста ошибки. Буфер — максимум 30 событий в памяти до перезагрузки, доступ через локальную консоль. Нет передачи на сервер и долговременного хранения. По умолчанию выключено.

## Не выполнено: внешний доступ или отдельное решение

1. Реальные слабый Android и Safari iOS: по 10 проходов, фон на 10–60 секунд, медленная сеть. Нужны подключённые устройства.
2. Настоящий тестовый Bitrix и проверка единственного созданного контакта: нужен согласованный контур. Локальная дедупликация не гарантирует единственность после перезапуска сервера или при неопределённом сетевом исходе, когда CRM могла принять запрос до обрыва ответа. Для такой гарантии нужна сверка на стороне CRM.
3. Утверждение контента сотрудником/кинологом фонда и затем проверенные альтернативы. Маркировка `needs-foundation-review` сохранена; одобрение не выдумано.
4. Сравнение мягкого укуса с полным сбросом требует пользовательских замеров и отдельного решения. Текущее правило не менялось.
5. Дальнейшее разделение игр по чанкам — после замеров на целевых устройствах. Здесь отдельно загружается генератор карточки, не переписывается сборка.
