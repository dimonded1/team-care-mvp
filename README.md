# Команда заботы — MVP

Отдельный greenfield-проект мобильного интерактива программы «Опека» фонда НИКА. В хабе и мини-играх используется единый мультяшный мир «планет заботы»; реальные фотографии подопечных остаются в мэтчинге и story-карточке.

## Сценарий

1. Загрузка.
2. Стартовый экран.
3. 11 свайп-вопросов: вправо/«Да», влево/«Нет».
4. Мэтч и орбита одного животного.
5. Короткое визуальное объяснение: подопечный — Солнце, опекуны — планеты и защитный круг.
6. Четыре последовательных модуля опеки: знакомство, визит, прогулка, внимание к здоровью.
7. Объяснение опеки и команды до пяти опекунов.
8. Финал, CTA и PNG-карточка для сохранения/шеринга.

Локально сохраняется только анонимный прогресс. В production-сборке есть server-only Node endpoint для лёгкой заявки «оставить контакт». Интеграция с Битрикс24 выключена по умолчанию; webhook и секрет никогда не попадают в Vite-клиент. Все точки настройки находятся в [`integrations/bitrix`](integrations/bitrix/README.md) и [`.env.example`](.env.example).

## Локальный запуск

```bash
npm ci
npm run dev
```

## Проверки

```bash
npm run test
npm run build
npm run test:server
```

После запуска Docker полный мобильный smoke-тест (реальный свайп, 11 вопросов, четыре ситуации и генерация карточки) выполняется так:

```bash
npm run smoke
```

Скриншоты проверки сохраняются локально в `artifacts/` и не коммитятся.

## Docker

```bash
docker compose build
docker compose up -d
```

Приложение будет доступно на `http://localhost:8080`. Runtime использует non-root Node, read-only filesystem, healthcheck, CSP и другие security headers.

### Подготовка `.env` на сервере

1. Скопировать `.env.example` в `.env` непосредственно на сервере.
2. Выставить права `chmod 600 .env`.
3. Вставить HTTPS webhook, сгенерированный server-only секрет, подтверждённые ID полей и публичный origin.
4. Сначала оставить `BITRIX_ENABLED=false` и `BITRIX_CONTACTS_ENABLED=false`, поднять контейнер и проверить `/healthz`.
5. Проверить один тестовый контакт в Bitrix, затем включить только два флага выше.

`APP_TRUST_PROXY=true` допустим только за доверенным reverse proxy, который перезаписывает `X-Forwarded-*`. Для одного контейнера оставить `false`. Enum ID трёх вариантов интереса нужно получить у администратора Bitrix; до этого выбранный вариант безопасно сохраняется в `COMMENTS`.

### Обновление каталога подопечных

В `.env` укажите обе воронки:

```dotenv
BITRIX_ANIMAL_CATEGORY_ID=17
BITRIX_ANIMAL_CATEGORY_IDS=17,13
```

Затем выполните `npm run sync:animals`. Команда постранично читает все
опубликованные карточки из настроенных воронок и обновляет полный серверный
каталог. В клиентский снимок для GitHub Pages/production build автоматически
попадают только животные с проверенным профилем из
`src/data/animalEditorial.json`. Исходящие feature-флаги можно и нужно
оставлять выключенными: скрипт временно включает только read-only контур внутри
своего процесса. Точный состав полей, результат последней синхронизации и схема
мэтчинга зафиксированы в [`ANIMAL-DATA-AUDIT.md`](ANIMAL-DATA-AUDIT.md).
